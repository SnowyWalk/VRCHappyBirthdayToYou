# Birthday World Atlas Protocol — BWAT v1

이 문서는 **다른 웹 프로젝트에서 단독으로 참고해 구현할 수 있는 확정 규약**입니다.
현재 문서의 네트워크·닉네임 규약은 **v1.1 amendment**를 포함합니다.
BWAT 바이너리 형식 버전 byte는 계속 1이며, 사진 geometry와 CRC 계산 방식은 바뀌지 않습니다.
웹사이트는 사진과 패널 배치를 PNG 한 장에 담아 게시하고, 생일자 닉네임은 PNG URL의
`name` query parameter에 담습니다.
VRChat 월드는 그 PNG의 URL을 한 번 입력받아 모든 전시 패널과 URL 닉네임을 적용합니다.
문서의 헤더·배치 조건은 월드 디코더가 검사합니다. 파일 게시 조건은 웹서비스가 보장해야 합니다. 예전 `UrlContentPlan.md`보다
이 문서를 우선합니다. 웹사이트 주소는 아직 정해지지 않았습니다.

## 1. 사용 흐름과 네트워크 계약

1. 웹에서 생일자 닉네임을 입력하고, 전경 이미지의 패널을 클릭해 사진을 등록한다.
2. 각 패널에 가로 16:9 / 세로 9:16 / 사진 없음 중 하나를 지정한다.
3. 가로·세로 비율이 다른 원본은 웹 편집기에서 crop 또는 여백을 선택하여 맞춘다.
   방향 판정은 EXIF 방향 보정 이후에 한다. 월드는 PNG에 적힌 방향을 따른다.
4. 아래 규약의 PNG를 만들고, URL에 닉네임 `name` parameter를 붙인
   **VRChat용 이미지 링크 복사** 버튼을 제공한다.
5. 사용자가 스폰 근처의 URL 입력 필드에 붙여넣고 입력을 확정하거나 적용 버튼을 누른다.
6. 월드는 전체 URL을 다운로드하고 헤더 전체를 검증한 후 사진·패널 활성 상태·URL 닉네임을 교체한다.

게시 URL은 `https://HOST/party/IMMUTABLE_ID/atlas.png?name=...` 같은 **PNG 직접 주소**여야 한다.
GET은 `name` query를 포함한 전체 URL에 대해 인증·쿠키·로그인·리다이렉트 없이
HTTP 200과 `Content-Type: image/png`을 반환한다.
HTML 공유 페이지 주소는 사용할 수 없다. 일반적인 사진 호스팅 서비스가 이미지 크기를
변경하거나 JPEG로 변환하면 헤더가 손상되므로 **원본 바이트를 보존하는 저장소**를 사용한다.
이벤트를 수정할 때마다 새 immutable URL을 발급한다. 같은 URL의 내용을 덮어쓰지 않는다.
서명된 URL처럼 기존 query가 있으면 `&name=...`을 마지막에 추가한다.
호스트는 `name` parameter를 무시하고 query가 없는 같은 PNG 주소와 **동일한 PNG 바이트**를 반환해야 한다.
크로스오리진 웹 편집기 사용 시 CORS는 웹 구현에서 처리한다. VRChat에는 CORS가 해결책이 아니다.

Worlds SDK는 이미지 최대 2048×2048, 요청 간격 클라이언트 전체 5초, 리다이렉트 금지를
적용한다. 런타임 문자열로 새 VRCUrl을 생성할 수 없으므로, 월드는 사용자가 입력한
**원본 VRCUrl 그대로** 다운로드한다. 외부 JSON의 임의 이미지 URL 목록을 사용하는
방식으로 바꾸지 않는다. 자체 도메인은 각 유저의 **Allow Untrusted URLs** 설정이 필요할 수 있다.
이 설정을 월드가 자동으로 켤 수는 없다.

## 2. PNG 조건 — MUST

- 크기: **정확히 2048×2048 픽셀**.
- 색상: **8비트 RGB 또는 RGBA**, PNG lossless. 팔레트·그레이스케일·16비트 PNG를 사용하지 않는다.
- RGB 값은 일반 sRGB 색상이며, 데이터 흑백 셀은 정확히 0 또는 255다.
- 출력 알파는 전체 255(불투명). EXIF 방향은 굽고 최종 파일에 방향 변환을 남기지 않는다.
- 사진은 RGB로 합성하며, 투명 원본은 배경에 합성한다.
- top-left PNG 좌표 기준 `y=0..63`은 데이터 전용 영역이다.
- 사진별 사방 **4픽셀 gutter**를 둔다. 사진 경계 픽셀을 gutter에 반복해서 늘린다.
  좌표 레코드에는 gutter를 제외한 **사진 내부 사각형**만 기록한다.
- 등록되지 않은 패널은 공간을 차지하지 않는다. 남은 공간은 배경색으로 채운다.

## 3. 패널 ID — 순서와 위치는 고정

모든 헤더에 8개 레코드를 포함한다. 레코드 인덱스는 panel ID와 같아야 한다.
웹에서 어느 패널을 클릭했는지 ID로 저장한다. 아틀라스 안의 위치와 월드 위치는 독립적이다.

| ID | 웹용 안정 이름 | Unity 패널 루트 | 월드 중심 좌표 X / Y / Z |
|---:|---|---|---|
| 0 | portrait-left | Hero portrait -1 | -6.15 / 2.30 / 6.80 |
| 1 | gallery-left-1 | Memory -1 0 | -7.40 / 1.65 / 2.80 |
| 2 | gallery-left-2 | Memory -1 1 | -7.65 / 1.65 / -0.45 |
| 3 | gallery-left-3 | Memory -1 2 | -6.75 / 1.65 / -3.70 |
| 4 | portrait-right | Hero portrait 1 | 6.15 / 2.30 / 6.80 |
| 5 | gallery-right-1 | Memory 1 0 | 7.40 / 1.65 / 2.80 |
| 6 | gallery-right-2 | Memory 1 1 | 7.65 / 1.65 / -0.45 |
| 7 | gallery-right-3 | Memory 1 2 | 6.75 / 1.65 / -3.70 |

`portrait-*`는 위치 이름일 뿐이다. **8개 패널 모두 가로·세로·빈칸을 지원**한다.
에디터 및 URL을 아직 적용하지 않은 월드에서는 8개 패널을 가로 16:9 자리표시자로 표시한다.
유효한 PNG를 적용한 뒤에는 등록된 사진의 가로/세로 방향에 맞추고, 미할당 패널은 숨긴다.
월드는 프레임 크기를 원본 방향에 맞게 조절하되 각 위치의 기존 최대 공간 안에 맞춘다.
웹 업로드 전경에서는 사진 방향과 미할당 상태를 그대로 미리 보여주는 것이 좋다.

현재 월드의 표시 영역 상한은 ID 0/4가 **3.00 × 3.05 m**, 나머지가
**2.25 × 2.45 m**이다. 실제 사진의 폭/높이는 상한 안에 16:9 또는 9:16을
비율 유지하여 맞춘다. 따라서 0/4 세로 사진은 1.715625 × 3.05 m,
나머지 세로 사진은 1.378125 × 2.45 m이다. 프레임은 사진 폭/높이에 각각
0.16 m, 뒤 인레이는 각각 0.06 m를 더한다. 패널 중심은 방향 전환에도 움직이지 않는다.
패널은 수직으로 서며 표시 면(local -Z)이 홀 중심 X=0, Z=1.5를 향한다.
월드 미적 배치는 바뀔 수 있으나 패널 ID와 바이너리 인덱스는 유지한다.

## 4. 256바이트 바이너리 헤더 — MUST

모든 다중 바이트 정수는 unsigned **little-endian**이다. 패딩·예약 필드는 반드시 0이다.

| offset | bytes | 값 |
|---:|---:|---|
| 0 | 4 | ASCII `BWAT` = `42 57 41 54` |
| 4 | 1 | 형식 버전 = 1 |
| 5 | 1 | 활성 패널 개수 = 0..8 |
| 6 | 1 | v1.1 신규 encoder는 0. legacy embedded nickname 길이 0..128은 수신기가 유효 헤더로는 받아도 표시에는 사용하지 않음 |
| 7 | 1 | 예약 = 0 |
| 8 | 4 | 콘텐츠 revision, uint32; 웹 게시 버전. World sync 카운터와는 별개 |
| 12 | 2 | atlas width = 2048 |
| 14 | 2 | atlas height = 2048 |
| 16 | 2 | 데이터 영역 높이 = 64 |
| 18 | 2 | 패널 레코드 길이 = 12 |
| 20 | 96 | 아래 패널 레코드 8개, ID 순서대로 |
| 116 | 128 | 예약 = 0. legacy embedded nickname 바이트는 수신기가 유효 헤더로는 받아도 표시에는 사용하지 않음 |
| 244 | 8 | 예약 = 0 |
| 252 | 4 | CRC-32/ISO-HDLC, 아래 정의 |

패널 i의 레코드는 `offset = 20 + 12*i`에서 시작한다.

| 레코드 offset | bytes | 값 |
|---:|---:|---|
| 0 | 1 | panel ID = i |
| 1 | 1 | flags, 아래 비트 정의 |
| 2 | 2 | 사진 내부 x, top-left PNG 좌표 |
| 4 | 2 | 사진 내부 y, top-left PNG 좌표 |
| 6 | 2 | 저장된 사진 내부 width |
| 8 | 2 | 저장된 사진 내부 height |
| 10 | 2 | 예약 = 0 |

flags:

- bit 0 (`1`): 패널 활성.
- bit 1 (`2`): **원래 표시 방향**이 세로. 0이면 가로.
- bit 2 (`4`): 사진을 원래 방향에서 **90도 시계 방향**으로 돌려 저장했다.
- bit 3..7: 예약, 반드시 0.

빈 패널의 flags·x·y·width·height·예약값은 모두 0이며, ID만 i다.
활성 패널은 x≥4, y≥68, x+width+4≤2048, y+height+4≤2048이어야 한다.
서로 다른 사진의 **gutter 포함 사각형은 겹치면 안 된다**. 활성 개수는 offset 5와 같아야 한다.

원래 사진 크기는 회전 플래그가 0이면 `(width,height)`, 1이면 `(height,width)`다.
가로는 정확히 `(16k,9k)`, 세로는 `(9k,16k)`인 양의 정수 k를 사용한다.
수신기는 서로 다른 k도 허용하지만 아래 권장 배치는 모든 사진의 k를 동일하게 최대화한다.

## 5. URL 닉네임과 CRC — MUST

### v1.1 amendment

닉네임은 헤더가 아니라 사용자가 입력한 PNG URL의 `name` query parameter에서만 읽는다.
웹은 JavaScript `encodeURIComponent`와 같은 UTF-8 percent encoding으로 `name` 값을 만든다.
공백은 `%20`을 권장하지만 수신기는 form-style `+`도 공백으로 받아야 한다.
기존 query가 있는 signed URL은 `...?sig=...&name=...`처럼 `&name=`을 추가한다.
URL 안에 `name` parameter가 두 번 이상 있으면 유효하지 않은 URL이다.
`name` parameter가 없으면 닉네임은 빈 문자열로 지운다.

웹에서 닉네임을 NFC 정규화한 뒤 percent encode한다. 수신기는 정규화를 다시 하지 않고
percent decode한 Unicode의 UTF-8 바이트를 검사한다. URL 닉네임은
**문자 수가 아니라 바이트 수로 128 이하**여야 한다. 초과하면 저장 전에 사용자에게
줄이도록 안내한다. 중간 바이트를 잘라내지 않는다. 잘못된 UTF-8,
U+0000..U+001F, U+007F는 허용하지 않는다.
닉네임은 서식 없는 텍스트로 표시하며 TMP rich text를 끈다.
폰트에 없는 이모지/특수 문자는 표시가 보장되지 않으므로 웹 미리보기에도 안내할 수 있다.

신규 encoder는 offset 6을 0으로 쓰고 bytes 116..243을 모두 0으로 예약한다.
legacy v1 PNG에 유효한 embedded nickname이 있어도 월드는 헤더 검증과 사진 적용은 허용하되,
표시 닉네임으로는 사용하지 않는다. URL `name`이 항상 권위(authoritative)를 가진다.

CRC는 **바이트 0..251 전체**에 대한 CRC-32/ISO-HDLC다.
reflected polynomial `0xEDB88320`, initial `0xFFFFFFFF`, final XOR `0xFFFFFFFF`.
Python `binascii.crc32(header[:252]) & 0xffffffff`와 같은 결과를 사용한다.
CRC 결과 uint32를 offset 252에 little-endian으로 기록한다.
CRC·버전·크기·좌표·flags·UTF-8 검증에 실패하면 월드는 이전 콘텐츠를 유지한다.

## 6. 헤더를 픽셀에 기록하는 법 — MUST

전체 256바이트 = 2048비트를 8×8픽셀 흑백 셀 2048개로 표현한다.
상단 데이터 영역은 가로 256셀 × 세로 8셀이다.

비트 인덱스 j=0..2047에 대해:

```text
byteIndex = floor(j / 8)
bitIndex  = 7 - (j % 8)       # 각 바이트 MSB 먼저
bit       = (header[byteIndex] >> bitIndex) & 1
cellX     = (j % 256) * 8
cellY     = floor(j / 256) * 8
```

`[cellX,cellX+7] × [cellY,cellY+7]` 전체를 bit=0이면 RGB(0,0,0),
bit=1이면 RGB(255,255,255), 알파255로 칠한다. 셀 사이 여백·안티앨리어싱을 넣지 않는다.
셀 중심의 검정/흰색을 읽으므로 중간 RGB 숫자값·sRGB 감마 변환에 의존하지 않는다.

월드는 shader로 8비트를 한 바이트로 복원한 뒤, **64×1 linear RGBA32** 텍스처에
pixel i의 R/G/B/A에 header[4i+0..3]을 기록한다. 비동기 GPU readback은 이 작은
텍스처에 한 번 요청한다. 원본 4백만 픽셀을 매 프레임 읽지 않는다.

## 7. 회전 복원과 UV

PNG에서 사진 내부를 자른 뒤 rotation=1이면 **90도 반시계 방향**으로 돌려야 원본이 된다.
웹 저장에서는 Pillow `Image.Transpose.ROTATE_270`이 시계 방향 저장에 해당한다.
원래 사진의 top-left 정규 좌표 `(u,v)`를 저장된 사진으로 매핑하면 `(1-v,u)`다.
Unity의 bottom-left UV 기준으로는 `(u,v) -> (v,1-u)`다.

Unity 아틀라스 사각형:

```text
offsetU = x / 2048
offsetV = (2048 - y - height) / 2048
scaleU  = width / 2048
scaleV  = height / 2048
storedUV = rotation ? (sourceUV.y, 1-sourceUV.x) : sourceUV
atlasUV  = offset + storedUV * scale
```

rotation은 저장 방식이며, 원본이 세로라는 bit 1과 독립적이다.
corner 테스트는 원래 사진의 왼쪽 위 빨강 / 오른쪽 위 초록 / 왼쪽 아래 파랑 /
오른쪽 아래 노랑이 월드에서도 같은 위치로 표시되는지 확인한다.

## 8. 최적 배치와 해상도

가로/세로/빈칸 8개 슬롯은 3^8=6,561개 조합이다. 저장 회전을 허용하면 같은 비율의
사진은 모두 같은 사각형이므로, 사진 개수 0..8별 템플릿 9개로 모두 처리할 수 있다.
공통 정수 k를 최대화하는 조건이며, 원본 크기·물리적 패널 크기·개별 중요도는 별도 고려다.
정확히 같은 k를 적용하면 작은 원본이 업스케일될 수 있으므로 웹에서 경고하거나
해당 사진만 더 작은 같은 비율의 사각형으로 저장하는 것도 규약상 허용된다.

| 등록 수 | k | 원래 가로 사진 px | 원래 세로 사진 px |
|---:|---:|---|---|
| 0 | 0 | 없음 | 없음 |
| 1 | 127 | 2032×1143 | 1143×2032 |
| 2 | 112 | 1792×1008 | 1008×1792 |
| 3 | 81 | 1296×729 | 729×1296 |
| 4 | 78 | 1248×702 | 702×1248 |
| 5 | 63 | 1008×567 | 567×1008 |
| 6 | 63 | 1008×567 | 567×1008 |
| 7 | 59 | 944×531 | 531×944 |
| 8 | 57 | 912×513 | 513×912 |

아래 템플릿 JSON은 외부 파일 없이 이 문서만으로 구현할 수 있도록 포함했다.
`kind=L`은 **저장 사각형**이 가로, P는 세로라는 뜻이다.

패널 할당 알고리즘:

1. 활성 패널을 ID 순서대로 모으고 사진 수 N의 템플릿을 선택한다.
2. 가급적 원래 방향과 kind가 같은 빈 사각형에 배정한다.
3. 남은 사진은 남은 사각형에 배정하고 방향이 다르면 시계 방향으로 90도 회전해 저장한다.
4. panel ID와 원래 방향, 회전 여부, 저장 사각형 좌표를 해당 ID의 레코드에 기록한다.
5. 미할당 패널은 disabled 레코드로 기록한다. offset 6과 bytes 116..243을 0으로 두고 CRC를 기록한 뒤 흑백 셀을 그린다.

## 9. 웹 구현과 월드 검증 체크리스트

- URL `name` parameter에서 닉네임 한국어·일본어·영문·공백을 UTF-8로 왕복 검증한다.
- `name` parameter가 없으면 닉네임이 지워지고, 중복 `name`은 실패하는지 확인한다.
- 8개 패널의 위치와 ID를 실제 월드와 일치시킨다.
- 0장 / 1장 / 8장 / 가로·세로 혼합 / 가운데 빈칸을 각각 테스트한다.
- EXIF 적용, crop/여백, 시계 방향 저장, 반시계 방향 복원을 확인한다.
- PNG 저장 전후 header256바이트가 동일한지 셀 중심에서 복원해 비교한다.
- CRC가 틀리거나 사진이 겹치는 PNG는 월드에서 기존 화면을 유지해야 한다.
- 게시 이후 파일 최적화/CDN 변환으로 헤더가 바뀌지 않는지 실제 GET 파일을 비교한다.
- 월드는 사용자가 입력한 전체 URL과 sync revision을 동기화한다. 신규 입장자는 같은 PNG를 직접 다운로드한다.
  다운로드 속도 때문에 모든 클라이언트가 같은 프레임에 적용하는 것은 보장하지 않는다.
- PC/Quest 지원 범위에 맞춰 GPU readback과 UI 입력을 실제 클라이언트에서 테스트한다.
- VRChat에는 임의 OS 클립보드 쓰기 API를 전제하지 않는다. 웹 주소는 선택·복사 가능한
  readonly 필드로 표시한다. 이미지 URL 입력에는 실제 `VRCUrlInputField`를 사용한다.

### Legacy v1 embedded-name acceptance vector

아래 벡터는 legacy v1 PNG 수신 호환성 검증용이다. 패널 패턴은 `PLELPELL`,
